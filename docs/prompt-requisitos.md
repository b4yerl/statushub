Atue como um **Product Owner e Analista de Requisitos de Software**.

Seu papel é **criar um projeto completo de estudo**, do zero, com base apenas nas informações que eu fornecerei abaixo.  
Você deverá **definir a ideia do sistema, seu público, objetivos, funcionalidades e requisitos técnicos**, como se fosse um produto real.

---  
📘 **Instruções principais**
1. Crie um **conceito original** de aplicação coerente com as tecnologias e o grau de complexidade informados.
2. O projeto deve ser realista o suficiente para um estudo técnico, mas factível de ser implementado individualmente.
3. Estruture a resposta em seções bem organizadas, conforme abaixo.

---  
📋 **Informações fornecidas por mim**
- **Tecnologia principal ou stack desejada:** [INSIRA AQUI, ex: Quarkus + React Native | Node.js + Vue | Python + Flask]
- **Nível de complexidade desejado:** [básico | intermediário | avançado]
- (Opcional) **Tipo de aplicação preferido:** [web | mobile | desktop | API | híbrido]
- (Opcional) **Foco principal de aprendizado:** [ex: integração de API, autenticação JWT, persistência, UI, arquitetura, etc.]

---  
🎨 **Instruções para você (o PO/Analista)**
Com base apenas nas informações acima, gere:

1. 🧠 **Resumo do Produto**  
   - Nome sugerido do projeto  
   - Ideia central e problema que resolve  
   - Público-alvo e caso de uso  
   - Escopo geral do sistema

2. ⚙️ **Requisitos Funcionais**  
   - Liste e numere as principais funcionalidades  
   - Organize por módulo ou área lógica (ex: autenticação, dashboard, relatórios etc.)  
   - Cada requisito deve começar com verbo no infinitivo (ex: “Permitir que o usuário…”)  
   - Adicione exemplos ou observações curtas quando útil

3. 🧩 **Requisitos Não Funcionais**  
   Agrupe por categoria (ex: Desempenho, Segurança, Usabilidade, Manutenibilidade, Portabilidade, Escalabilidade).  
   Especifique metas realistas para o nível de complexidade informado.

4. 🔁 **Cenários de Uso ou User Stories** *(opcional, mas recomendável)*  
   - Inclua 3 a 5 user stories representativas, no formato:  
     “Como [tipo de usuário], quero [ação] para [benefício].”

5. ✅ **Critérios de Aceitação** *(opcional)*  
   - Defina condições de sucesso para algumas das principais funcionalidades.

6. 🚀 **Sugestões de Expansão**  
   - Liste ideias extras ou desafios técnicos opcionais para aprofundar o aprendizado (ex: cache, CI/CD, testes automatizados, Docker, etc.)

7. 🧭 **Resumo do Escopo de Estudo**  
   - Diga o que o estudante (eu) deve ser capaz de aprender ou praticar ao desenvolver o projeto.  
   - Se possível, relacione com boas práticas de engenharia de software.

---  
🎯 **Objetivo final**  
Entregar uma visão completa e coesa de um projeto de software para estudo, com requisitos bem definidos, totalmente inventado por você com base nos parâmetros fornecidos.
